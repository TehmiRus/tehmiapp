# ТехМИ — Аспирация для Android

Автономное Android-приложение по настольной программе
[TehmiRus/Filter-](https://github.com/TehmiRus/Filter-), версия 2.2,
исходный коммит `47ea2388f24556409192d5054de28a8911c5a9f3`.
Минимальная ОС: Android 7.0 (API 24). Нужен обновлённый Android System WebView
с поддержкой современного JavaScript (Chromium 92+).

## Возможности

- Фильтр: заданная инженером нагрузка или предварительная модель БНТУ;
  33 вида пыли, регенерация и материал, рабочий/нормальный расход,
  пересчёт сухого газа во влажный, независимое отключение секций,
  запас площади, подбор целого числа рукавов с проверкой net/gross-площади.
- Альтернатива: заданная скорость фильтрации либо перенос нагрузки с аналога,
  сравнение площадей, секции и подбор рукавов.
- Воздуховод: один круглый участок, диаметр, скорость, трение и местные потери.
- Вентилятор: потери полного давления, запас, мощность с учётом КПД.
- Пыль: вход, улавливание, выброс и выходная концентрация.
- Формулы, литература, ограничения моделей, отчёты TXT в UTF-8 с BOM.
- Ввод с точкой или запятой; независимое сохранение форм на устройстве.
  Результат сбрасывается при изменении данных. Сброс формы требует подтверждения.

Это предварительный инженерный калькулятор, не автоматическое проектирование
всей системы. Начальные значения — примеры. Применимость q, λ, ζ,
эффективности и исходных данных подтверждает инженер.

## Установка на телефон

Соберите `app-debug.apk` либо используйте подготовленный APK из результата работы.
Перенесите на телефон, откройте файл и разрешите установку из выбранного
источника, если Android запросит. Debug-подпись предназначена для тестирования;
публикация в магазине требует отдельной release-подписи.

Расчёты не требуют сети, Python или сервера. TXT сохраняется системным
выбором документа; доступ ко всему хранилищу не запрашивается.
Данные форм хранятся локально и удаляются при очистке данных приложения.

## Сборка

Android Studio: открыть корень проекта, установить SDK Platform 35 и
Build-Tools 34.0.0 (версия по умолчанию AGP 8.7.3), дождаться Gradle Sync,
выбрать Build APK или Run на подключённом телефоне.

Командная строка: полный JDK 17 или 21, Android SDK 35, Gradle Wrapper 8.9:

```sh
export JAVA_HOME=/path/to/jdk
export ANDROID_HOME=/path/to/android-sdk
./gradlew --no-daemon --max-workers=2 :app:assembleDebug :app:lintDebug
```

Windows: `gradlew.bat :app:assembleDebug :app:lintDebug`.
Результат: `app/build/outputs/apk/debug/app-debug.apk`.
Не добавляйте `local.properties`, SDK, ключи или секреты в Git.

В текущей облачной среде инструменты установлены вне репозитория:

```sh
. /workspace/android-tools/env.sh
./gradlew --no-daemon --max-workers=2 :app:assembleDebug :app:lintDebug
```

У Gradle в этой среде настроены прокси и системное доверие CA во внешнем
`GRADLE_USER_HOME`; на обычном ПК эти настройки не нужны.
Каждая облачная задача изолирована: используйте существующий checkout,
не создавайте worktree без отдельного запроса. Изменения настроек среды
и публикация среды в рамках этой реализации не выполняются.

## Проверки

Без установки зависимостей, Node.js 18+:

```sh
node tests/engine.test.cjs
```

1161 сценарий с ожидаемыми значениями Python-версии: пыли, граничные
диаметры, все способы регенерации, случайные геометрии, нормальный/влажный
расход и ошибки ввода. Fixture `tests/reference-cases.json` получен из
исходного коммита Python, не из проверяемого JS-ядра. Относительный допуск
сравнения 1e-10; это проверка переноса, не точность инженерной модели.
Дополнительно проверены отчёт, активные поля и ввод. При количестве рукавов
выше точного целого диапазона JavaScript расчёт отклоняется.

UI-тест с Playwright (установите `playwright` и Chromium):

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory app/src/main/assets
# Во втором терминале:
node tests/ui.test.cjs
```

В UI-тесте путь Chromium задаётся `CHROMIUM_PATH` (по умолчанию `/usr/bin/chromium`).
Проверены пять расчётных панелей, БНТУ, валидация, устаревание результата,
сохранение ввода, экспорт, навигация и ширины 320/390/768 px.
Скриншот: `docs/android-filter.png`. Физический телефон и Android-эмулятор
не использовались; проверка системного диалога сохранения на устройстве
остаётся отдельной проверкой.

## Структура и безопасность

`app/src/main/assets/engine.js` — расчётное ядро, `spec.js` — точный перенос
полей и справочников, `ui.js` — интерфейс. Java Activity отображает локальные
assets в WebView и сохраняет отчёт через Storage Access Framework.
Нет INTERNET и storage permissions, удалённых зависимостей в UI, CDN и
доступа WebView к file/content URL. Сетевые запросы перехватываются; разрешён
только фиксированный локальный origin с именами файлов без обхода каталогов.
CSP запрещает inline-скрипты и подключения. JavaScript необходим для расчётов;
доступный bridge ограничен сохранением TXT, размер отчёта ограничен.
Ссылки литературы показаны в тексте и автоматически не открываются.

Математика и исходные ограничения: `docs/MATH_AND_SOURCES.md`,
`docs/ASPIRATION_METHODS.md`, `docs/CONTROL_EXAMPLE.txt`.
Внешняя независимая верификация литературы в этом переносе не выполнялась.
Предыдущая заготовка калькулятора шнека заменена приложением аспирации;
её исходное состояние доступно в истории Git.
